## 1. Goal

Grow the knowledge base from 14 Persian articles into a solid, web-researched,
Iran-specific reference covering residential electricity and gas saving —
~**52 articles across 11 clusters** — with every article **course-ready**
(quiz-able key facts, learning objectives, cited sources, reading time).
Content lands live in the chatbot's grounding as each cluster merges.

One correction to the in-chat design message: the existing corpus is **14**
articles (not 18), so the split is **14 upgrades + 38 new = 52**.

## 2. Locked decisions (with user, 2026-10-04)

## 4. Article schema

**Frontmatter** (extends `title/category/tags`; flat list fields parse like
`tags` today — JSON arrays or comma lists):

```markdown
---
title: کاهش مصرف کولر گازی (اسپلیت)
category: cooling
tags: ["کولر گازی", "اسپلیت", "تابستان"]
utility: electricity          # electricity | gas | both
difficulty: starter           # starter | medium | deep
minutes: 4                    # reading time
sources: ["SATBA — sagp.ir/tariffs", "توانیر — تعرفه ۱۴۰۴"]
objectives: ["تنظیم درست دمای کولر", "چک‌لیست نگهداری ماهانه"]
keyFacts: [
  "هر یک درجه پایین‌تر در تابستان ≈ ۷ تا ۱۰ درصد مصرف بیشتر",
  "کولر اینورتر تا ۴۰–۶۰ درصد کم‌مصرف‌تر از غیراینورتر هم‌ظرفیت است"
]
---
```

**DB migration (drizzle 0003):** `kb_articles` gains nullable columns
`utility TEXT`, `difficulty TEXT`, `minutes INTEGER`, `sources TEXT`
(JSON array), `objectives TEXT` (JSON array), `keyFacts TEXT` (JSON array).
Reads apply defaults when null: `utility ?? "both"`, `difficulty ??
"starter"`, `minutes ?? 4`, `sources/objectives/keyFacts ?? []`.
`saveArticle` input extends with these fields; the frontmatter parser
(`lib/kb/frontmatter.ts`) parses the four new list/scalar fields with the
same leniency as `tags`.

`keyFacts` is the v3 quiz mine: each fact is one MCQ candidate. Articles aim
for **4–8 keyFacts** and **2–4 objectives**.

`sources` lives in frontmatter only — **not** rendered into the article body
— so grounding chunks stay noise-free. Chat prompts and the future v5
article pages consume `sources` from the column.

## 5. Seed reconciliation (upsert, replaces first-run-only seeding)

`ensureSeeded` becomes a reconciler that runs **once per process boot**
(guarded by a module-level flag; `instrumentation.ts` remains the boot
call site, `chat/context.ts` keeps its lazy call):

1. Walk `src/content/kb/**.md`; collect file slugs.
2. Per file → row by slug:
   - no row → insert (`source: "seed"`, published, indexed);
   - row with `source: "seed"` and any of
     title/bodyMd/category/tags/utility/difficulty/minutes/sources/objectives/keyFacts
     changed → update + re-chunk + re-index;
   - row with `source: "admin"` → **skip** (manual edits always win).
3. Orphan cleanup: rows with `source: "seed"` whose slug is not in the files
   are deleted (cascade removes chunks; FTS rows dropped first). Rows with
   `source: "admin"` are never deleted by reconciliation.

Admin-edit protection: the admin KB save path flips `source` from `"seed"`
to `"admin"` on update, so subsequent reconciliations skip that article.
Trade-off (accepted): a seed-updated article the admin edited will not
receive upstream content updates — by design.

## 6. Research & sourcing policy

Per cluster, **research precedes drafting**: web-research agents compile a
cited fact sheet (numbers + source name + URL) for the cluster's article
titles; drafts are written from the fact sheet, not from memory.

- **Iran-specific numbers** (تعرفه پلکانی، سهمیه گاز، خرید تضمینی ساتبا،
  برچسب انرژی ملی، ضریب شهرها…) must trace to Iranian official or
  reputable sources: وزارت نیرو، ساتبا، توانیر، شرکت ملی گاز، توزیع برق
  (regional cos.), and reputable energy press (ایسنا، مهر، دنیای انرژی).
- **General engineering numbers** (appliance wattages, insulation R-values,
  standby draw…) cross-check against international references (Energy Star,
  IEA, manufacturer specs).
- **Volatile figures are dated** in text («تعرفه‌های ۱۴۰۴…») and carry a
  year tag; articles state that tariffs revise annually.
- Every load-bearing number in an article maps to an entry in `sources`
  (2–6 per article). If a number cannot be sourced, it is dropped or
  replaced with a conservative range — never shipped unsourced.
- Safety-critical content (`safety` cluster, CO, gas leak) sticks to
  official guidance and avoids novel advice.

## 7. House-style contract (matches the existing 14)

Persian, informal «شما», emoji-light accents, **fa-digits**; H2-numbered
sections with bullets; key numbers **bolded**; 700–1000 words; every
article ends with **«یک قدم اول پیشنهادی»** — one concrete same-day
action. New articles match the tone of `cooling/01-ac-savings.md` (the
reference exemplar).

## 8. Production workflow

Isolated branch (`kb-expansion`, worktree). Order:

1. **Task 0 — enablement code** (TDD, first tasks of the plan): schema
   migration + frontmatter fields + `saveArticle` extension + seed
   reconciliation (§5) + admin `source` flip. Suite green; existing 14
   articles pass through reconciliation unchanged (they gain default
   metadata).
2. **Cluster 0 — upgrade existing 14**: file moves per §3, new categories,
   metadata filled, numbers spot-refreshed. → **user checkpoint** (calibrates
   tone before 38 new articles are written).
3. **Clusters 1–11** in §3 order, each: research fact sheet → drafts →
   internal quality pass (style contract + sourcing policy + keyFacts
   count) → **user checkpoint** → commit + merge to the working branch.
   12 checkpoints total; each is a skim of ~3–6 articles (readable in the
   admin KB editor, which renders markdown).
4. **Finish**: full suite + tsc + build, roadmap §9 update (v2.7 shipped),
   whole-branch review, then finishing-a-development-branch.

Commits: one per cluster (content), separate commits for Task 0 code; every
commit message ends with the attribution line per repo convention.

## 9. Testing

- **Frontmatter**: new fields parse (JSON-array and comma-list forms);
  defaults applied for missing fields; old files (title/category/tags only)
  still parse.
- **Reconciliation matrix** (in-memory SQLite): insert new; update changed
  seed row (re-chunked, FTS rebuilt); skip admin row; delete orphaned seed
  row; keep orphaned admin row; idempotent second run is a no-op; once-per-boot
  guard.
- **Migration**: drizzle 0003 applies cleanly over an existing DB with data;
  defaults surface on read.
- **Regression**: chat grounding (`searchKb`) unaffected; full suite stays
  green after Task 0 and after every cluster.
- Content correctness is enforced by process (fact sheets + user
  checkpoints), not by automated tests.

## 10. Consumption downstream

- **v3 courses**: course lessons map to articles via `category` + slug;
  MCQ candidates derive from `keyFacts`; TTS scripts excerpt the body and
  `objectives`; difficulty ladder uses `difficulty`.
- **Chat grounding**: benefits immediately as clusters merge (more chunks in
  FTS5); prompt builder may cite `sources` names when answering from an
  article.
- **v5 SEO**: article pages render `sources` as a «منابع» footer;
  `minutes` feeds reading-time badges; clusters become site sections.

## 11. Out of scope

- Course/lesson/TTS/multimedia **production** (v3 — this phase only
  prepares the raw material).
- Public article pages on the website (v5).
- Admin-editor UI for the new metadata fields (files remain the source of
  structured fields; admin body edits are preserved via the `source` flip).
- Renaming the chat pipeline or search ranking; English content; water
  utility as a first-class `utility` value (articles mention water-saving
  only where it saves hot-water energy).

## 12. Risks

- **Tariff churn**: annual revisions date articles; mitigated by dating +
  tags; reconciliation makes pushing updates a file edit.
- **Source reliability**: mixed-quality Persian web sources; mitigated by
  preferring official domains and cross-checks, dropping unsourced numbers.
- **Review fatigue**: 12 checkpoints; each is intentionally a skim
  (3–6 short articles), and cluster 0 calibrates tone early.
