# Admin bill viewer + suggestion regenerate/send — Design

**Date:** 2026-06-30
**Status:** Approved (pending spec review)

## Goal

Let an admin, from the existing user-detail page in the admin UI:

1. **See the bills of a user** — list a user's inquired bills with their details and the currently stored AI suggestions.
2. **Regenerate the AI suggestions for a bill**, review the result (preview), and then **send** the suggestions to that user via their Bale chat.

## Background (current behavior)

- Bills are produced by Finnotech inquiry and stored in `Bill` (`billing/repository.py`). `recent_bills(user_id, limit)` already returns a user's bills newest-first.
- AI suggestions are generated by `billing/suggestions.py`:
  - `generate_and_send_suggestions(...)` → `_generate(...)` renders the `bill_suggestions` prompt, calls the provider router, parses JSON, stores onto `bill.suggestions`, appends the suggested *targets* to the user's profile `goals`, and posts the rendered text to the user's Bale chat.
  - It **short-circuits** when `bill.suggestions is not None` (re-sends the existing text) and writes via `set_bill_suggestions_if_absent` (never overwrites). So there is currently **no way to regenerate**.
  - Goal append (`ProfileRepository.append`) does **not** dedup — each generation appends a fresh copy of the targets as goals.
- Each suggestion-derived goal object carries `source == "bill_suggestion"` and `bill_id == str(bill.id)`, which uniquely identifies "this bill's goals".
- In Bale private chats, `chat_id == user.bale_user_id`. The admin send path uses `user.bale_user_id` as the chat id.
- Admin routers live under `src/energybot/admin_api/*.py`, each a FastAPI `APIRouter`, included in `main.py`, and guarded by the `current_admin` dependency.

## Design

### 1. `billing/suggestions.py` — separate generate / store / post / goals

Refactor so the LLM call + parse is reusable, without changing the existing bot path's behavior.

- **Extract** `async def _render_and_parse(bill, profile, prev, *, router, prompt_loader) -> dict | None` — renders the prompt, calls the router, parses JSON, and returns the suggestion **payload** (`generated_at`, `intro`, `tips`, `targets`, `model`, `prompt_version`) or `None` on provider/parse failure. Pure: no storage, no posting, no goal changes.
- **Existing bot path** (`_generate`/`generate_and_send_suggestions`): unchanged semantics — generate-if-absent (`set_bill_suggestions_if_absent`), append goals, post. Now implemented on top of `_render_and_parse`. The `area_m2`/`int-str` fix already landed; this refactor must keep `_build_suggestion_context` intact.
- **New** `async def regenerate_suggestions(*, bill_db_id, session_factory=None, router=None, prompt_loader=None) -> dict | None`:
  - Loads bill + profile + previous bill, calls `_render_and_parse` (ignoring any existing `bill.suggestions`).
  - On success, **overwrites** `bill.suggestions` via `set_bill_suggestions` (not `_if_absent`) and returns the payload.
  - Does **not** post and does **not** modify goals. This is the preview/draft step.
- **New** `async def send_suggestions(*, bill_db_id, session_factory=None, bale=None) -> bool`:
  - Loads the bill; if `bill.suggestions is None`, returns `False` (nothing to send).
  - Posts `render_suggestions(bill.suggestions)` to the user's Bale chat (`chat_id = user.bale_user_id`).
  - **Replaces this bill's goals**: via the new repo method below, drop existing goals where `source=="bill_suggestion"` and `bill_id==str(bill.id)`, then append the current `targets` (built with `_build_targets_as_goals`). Unrelated goals — including web-added string goals — are preserved.
  - Returns `True`.

### 2. `billing/repository.py` — goal replacement

Add `async def replace_bill_goals(self, user_id, bill_id: str, new_goals: list[dict]) -> None`:
- Loads the profile, rebuilds `goals` = `[g for g in goals if not (isinstance(g, dict) and g.get("source")=="bill_suggestion" and g.get("bill_id")==bill_id)] + new_goals`, writes back, recomputes completeness, and records a `ProfileEvent`. One commit (atomic w.r.t. the session).

### 3. `admin_api/bills.py` — new admin router

`APIRouter(prefix="/api/admin", tags=["admin-bills"])`, every route `Depends(current_admin)`:

- `GET /users/{user_id}/bills` → `{ "bills": [ {id, utility_type, amount, term, consumption, status, inquired_at, details, suggestions} ] }` using `recent_bills`. 404 if user not found.
- `POST /users/{user_id}/bills/{bill_id}/suggestions/regenerate` → calls `regenerate_suggestions`; returns `{ "suggestions": <payload> }`. 404 if the bill is missing or not owned by `user_id`; 502 if generation failed (returns `None`).
- `POST /users/{user_id}/bills/{bill_id}/suggestions/send` → calls `send_suggestions`; returns `{ "ok": true }`. 404 if bill missing/not owned; 409 if there are no stored suggestions to send. Writes an `AuditLog` row for the send (the user-facing action), consistent with how admin mutations are recorded.

Validation: confirm the bill's `user_id` matches the path `user_id` before acting. Register the router in `main.py`.

### 4. Admin UI — Bills tab on `users/[id]`

On `admin_ui/src/app/users/[id]/UserDetailClient.tsx`, add a **Bills** tab (alongside the existing sections), following current card/tab/button patterns:

- Fetches `GET /api/admin/users/{id}/bills` and renders each bill as a card: utility/term/amount/status/consumption, the bill `details`, and the current `suggestions` (intro/tips/targets) if present.
- Per bill: **Regenerate** button → POSTs `.../regenerate`, then renders the returned payload in place (preview) with a loading state. **Send to user** button → confirm dialog → POSTs `.../send`, shows success/error toast. Send is enabled whenever suggestions exist (re-send works without regenerating).

### 5. Error handling

- Generation failures (provider/parse) surface as HTTP 502 from regenerate; the UI shows an error and leaves any prior suggestion intact.
- Send with no suggestions → HTTP 409; the UI keeps the Send button disabled until suggestions exist.
- Bale post failures propagate as a 502-style error to the admin; goals are replaced only after a successful post (post first, then replace goals) so a failed send doesn't disturb the user's goals.

### 6. Testing

- **Unit (`billing/suggestions.py`, repository):**
  - `regenerate_suggestions` overwrites an existing `bill.suggestions` (with a fake router) and returns the payload; does not touch goals or post.
  - `send_suggestions` posts via a fake Bale client and, via `replace_bill_goals`, removes only this bill's prior goals while preserving other goals (including string goals) and adds the new targets. Returns `False`/409-path when no suggestions stored.
  - Existing bot path (`generate_and_send_suggestions`) behavior unchanged (regression test stays green).
- **Integration (`admin_api`):**
  - Endpoints require admin auth (401/403 without).
  - `GET .../bills` returns the expected shape and only the target user's bills.
  - `regenerate` returns a payload (fake router) and overwrites storage; `send` posts (fake Bale) and returns ok; ownership mismatch → 404; empty suggestions on send → 409.

## Out of scope (YAGNI)

- Editing suggestion text by hand before sending.
- A top-level "all bills across all users" page (this is per-user on the detail page).
- Scheduling / bulk regeneration.
