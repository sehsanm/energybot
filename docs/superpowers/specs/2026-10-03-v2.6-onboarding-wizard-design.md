# Design: v2.6 — In-App Onboarding Wizard

**Date:** 2026-10-03
**Status:** Approved (design); ready for implementation plan
**Owner:** Sehsanm
**Program context:** roadmap item v2.6 in `docs/2026-10-03-nextjs-rewrite-plan.md` §9 — after v2.5 (UI redesign, shipped), before v3 (courses + gamification + Gemini TTS).

---

## 1. Goal

Rebuild the legacy Bale onboarding experience (2026-07-12 redesign) as an
**in-app multi-step wizard** so every user gets a benefits-forward first run
that captures the full household profile, their motivation, a first bill, and
service preferences — feeding personalization today and v3 gamification
tomorrow. Works identically in the mini app (Telegram/Bale webviews, memory
navigation) and the plain browser, in the established Stitch design language.

## 2. Decisions (locked with user, 2026-10-03)

| Decision | Choice | Rationale |
|---|---|---|
| Bot vs app split | **Both; either completes.** Bot keeps lite 2-step chat onboarding; app offers the full wizard; completing either sets the same completion flag. Chat-first users are never forced into the mini app. |
| Entry UX | **Full-screen takeover** on first `/home` visit via a dedicated `/welcome` route; visible «بعداً» skip; resumable until completed. | Highest completion; skip keeps user in control. |
| Step fidelity | **Condensed ~7 screens** — same data as legacy, grouped fields. | Legacy parity of data without 11 taps. |
| Storage | Existing `profiles` JSON columns; **no schema migration.** | household/behaviour already carry these shapes. |
| Completion semantics | One shared flag in `profiles.behaviour.onboarding`; `POST /api/onboarding/complete` is idempotent. | Bot-lite and app converge on one gate. |
| v3 readiness | Wizard emits a single `onboarding_completed` event stub (no XP logic). | The exact hook v3 gamification subscribes to. |

## 3. Flow & screens (`/welcome`)

```
1 خوش‌آمد → 2 شهر و نوع منزل → 3 ساکنان و متراژ → 4 گرمایش/سرمایش/دغدغه
          → 5 انگیزه‌ها → 6 اولین قبض (skippable) → 7 ابزارها → celebration → /home
```

| # | Screen | Fields & controls | Rules |
|---|---|---|---|
| 1 | خوش‌آمد و مزایا | Benefits copy (cut bills, rewards, help the country); «شروع کن» primary, «بعداً» skip | Skip → `/home` (welcome card shows there); resumable |
| 2 | شهر و نوع منزل | `city` free text; `home_type` single-choice chips (آپارتمان، خانه ویلایی، دیگر) | city required, home_type required |
| 3 | ساکنان و متراژ | `occupants` stepper ۱–۸+; `area_m2` chips (<۵۰، ۵۰–۱۰۰، ۱۰۰–۱۵۰، بیش از ۱۵۰) | both required |
| 4 | گرمایش، سرمایش، دغدغه | `heating_type`, `cooling_type` single-choice chips (پکیج گازی، کولر گازی، …, نمی‌دانم); `main_concern` (برق / گاز / هر دو) | all required |
| 5 | انگیزه‌ها | Multi-select cards: `help_country`، `reduce_bill`، `earn_rewards` | ≥ 1 required |
| 6 | اولین قبض | Inline bill capture (typed ID + photo/PDF) reusing the bills pipeline; success → mini summary + «ادامه»; «فعلاً رد کن» skip | Skippable; skip does not block completion |
| 7 | ابزارها | Multi-select of 6 service prefs: `daily_reminder`، `cost_suggestions`، `reduce_help`، `weekly_summary`، `peak_alert`، `seasonal_tips` | None required; «تأیید» completes onboarding → Confetti → `/home` |

Chrome: progress bar on top; per-step «ادامه» disabled until valid; back
moves between wizard steps (own in-component memory stack — no pushState, so
it is safe inside webviews); every step commits to the profile immediately,
making resume trivial.

## 4. Data model (existing columns — no migration)

`profiles.household`: `city`, `home_type`, `occupants` (number), `area_m2`
(number — chip midpoints 40/75/125/200), `heating_type`, `cooling_type`,
`main_concern` (`"electricity" | "gas" | "both"`).

`profiles.behaviour`:
```json
{
  "motivations": ["reduce_bill", "earn_rewards"],
  "service_prefs": ["daily_reminder", "weekly_summary"],
  "onboarding": { "completed": true, "completedAt": 1760000000000, "source": "app" | "bot" }
}
```
Legacy-lite keys (`onb_step`) are left untouched for in-flight bot users.

## 5. API

- `PUT /api/profile` — reused for every step's partial save (household or
  behaviour merge; behaviour merge must be shallow-per-key so concurrent
  memory writes are not clobbered).
- `POST /api/onboarding/complete` — **new**; session-gated + CSRF; body
  `{ source: "app" | "bot" }` (default `app`); idempotently sets
  `behaviour.onboarding = { completed: true, completedAt: now, source }`;
  emits the `onboarding_completed` event stub; returns the updated profile.
  The write itself lives in a shared `markOnboarded(db, userId, source)`
  lib function so the bot handler (server-side, no HTTP hop) calls the same
  code the route does.
- `GET /api/me` — response gains `onboarded: boolean` (derived:
  `behaviour.onboarding?.completed === true`) so the client gate costs no
  extra round-trip.
- Bot handler (`lib/bot/handler.ts`): when lite onboarding finishes (the
  `onboardingDone` path), also call `markOnboarded(db, userId, "bot")` — the
  app then never shows the wizard to that user.

## 6. Entry & exit rules

- `/home` after session gate: `onboarded === false` → `router.replace("/welcome")`.
- `/welcome` itself is session-gated (same as other app pages); anonymous
  users follow the standard landing redirect.
- Skip («بعداً») → `/home`, which shows a compact «کامل کردن پروفایل» card
  until `onboarded` becomes true (replaces the plain first-bill empty-state
  when profile is empty).
- Resume: `nextIncompleteStep(profile)` derives the first step whose fields
  are missing — wizard state lives *in the profile*, so no separate state
  table and no stale-state bugs.
- Completed users hitting `/welcome` directly → redirect `/home`.

## 7. Components

- `src/lib/onboarding/steps.ts` — **pure**: step definitions (key, title,
  fields, validation), `nextIncompleteStep(profile)`, `isStepValid(step,
  draft)`, `profileFromDraft`/`draftFromProfile` mappers. Unit-tested like
  `lib/nav/userNav`.
- `src/app/welcome/page.tsx` — session gate + `WelcomeWizard`.
- `src/components/onboarding/WelcomeWizard.tsx` — state machine (current
  step, draft, memory back-stack), progress bar, step renderer; kit + shadcn
  primitives (chips, stepper, buttons) in the established design language.
- Step components co-located in `src/components/onboarding/steps/*`.
- `ProfileScreen` gains a compact «ابزارها» multi-select section editing
  `behaviour.service_prefs` — fulfilling the legacy «هر وقت خواستی عوضش کنی»
  promise.

## 8. Event stub (v3 hook)

`lib/events.ts` (new, tiny): `emitAppEvent(name, payload)` — for now logs
structured lines; `onboarding_completed` is the first (and only) event.
v3's gamification core replaces the logger with subscribers; no call sites
change.

## 9. Testing

- **Unit (steps.ts):** step order; `nextIncompleteStep` for fresh / partial /
  complete profiles; validation per step (required fields, occupants range,
  area chip mapping, motivations ≥ 1); draft↔profile mappers round-trip.
- **API:** complete endpoint — auth, CSRF, idempotency (double call → one
  completion event), source persisted; `/api/me` exposes `onboarded`
  correctly for all three states (absent / false / true).
- **Handler:** bot-lite completion sets the shared flag with `source: "bot"`.
- **Profile merge:** shallow behaviour merge preserves sibling keys.
- Existing suite stays green; screens verified by Playwright screenshots
  (browser mode; mini-app memory nav reasoned statically per the established
  ruling).

## 10. Out of scope

- Delivering on any toolbox preference (reminders, weekly summaries) — v4
  nudge engine territory; we only persist opt-ins.
- XP/badges/streak awards (v3) beyond the event stub.
- Re-running the wizard post-completion (profile screen remains the edit
  surface); i18n; the full 11-step bot chat wizard.
