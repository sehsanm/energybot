# v2.7 Knowledge-Base Expansion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow the Persian KB from 14 to 52 course-ready articles across 11 clusters — 4 code tasks (schema, parser, reconciliation) + a lint-harnessed upgrade task + 11 content-cluster tasks + wrap-up, all with user checkpoints.

**Architecture:** Enablement first: nullable `kb_articles` columns + drizzle migration, frontmatter fields, `saveArticle` extension (fixing the dropped `source` on update), then `ensureSeeded` becomes a boot-time reconciler (insert/update/skip-admin/orphan-cleanup). Content then lands cluster by cluster, gated by a content-lint test (`tests/kbContent.test.ts`) whose expected-slug fixture each cluster task extends — TDD for prose. Every cluster task ends with a mandatory user checkpoint before commit.

**Tech Stack:** Next.js 15 App Router, Drizzle+SQLite (better-sqlite3), drizzle-kit migrations, vitest (node env, in-memory SQLite via `makeTestDb()`), Persian markdown content in `web/src/content/kb/`.

**Spec:** `docs/superpowers/specs/2026-10-04-v2.7-kb-expansion-design.md`

## Global Constraints

- `web/` is the app root: tests `cd web && npx vitest run`, types `npx tsc --noEmit`, build `npm run build`. No new npm dependencies.
- Categories are exactly the 11 cluster slugs: `bills, cooling, heating, hot-water, kitchen, appliances, lighting, envelope, solar, safety, behavior`. Article files live at `web/src/content/kb/<cluster>/NN-english-slug.md` (2-digit number, kebab slug, unique across the whole tree).
- **Every article's frontmatter carries:** `title` (Persian), `category` (= parent dir), `tags` (≥2 Persian), `utility` (`electricity|gas|both`), `difficulty` (`starter|medium|deep`), `minutes` (int 2–15), `sources` (JSON array, 2–6 non-empty strings — source name + URL/detail), `objectives` (2–4 Persian phrases), `keyFacts` (4–8 short Persian facts, each quiz-able: a number, comparison, or rule).
- **House style (spec §7):** Persian, informal «شما», emoji-light, **Persian digits only** in prose (Latin/digits allowed solely inside latin runs like `A+`, `Inverter`, `R32`), H2-numbered sections with bullets, key numbers **bolded**, 700–1000 words (lint tolerance 600–1150), every article ends with an `## یک قدم اول پیشنهادی` section giving one same-day action. Exemplar: `src/content/kb/cooling/01-ac-savings.md` (after Task 5 it is the moved `electricity/03-ac-savings.md`).
- **Sourcing policy (spec §6):** research precedes drafting — a cited fact sheet (number → source name + URL) is written to the SDD workspace as `cluster-<n>-facts.md` before any article. Iran-specific numbers trace to Iranian official/reputable sources (وزارت نیرو، ساتبا، توانیر، شرکت ملی گاز، شرکت‌های توزیع برق، ایسنا/مهر/دیوانه‌ی اقتصاد → reputable energy press); general engineering numbers cross-check Energy Star/IEA/manufacturer specs; volatile figures are dated in text («تعرفه‌های ۱۴۰۴») and carry a year tag; **a number that cannot be sourced is dropped or replaced with a conservative range — never shipped unsourced**. Safety-cluster content sticks to official guidance only.
- **Checkpoints are hard stops:** every cluster task's final pre-commit step is a user checkpoint (spec §8). Present the cluster's file paths + titles; wait for the user's approval; apply flagged fixes; then commit. This plan mandates these pauses — they override continuous-execution defaults.
- Commit messages end with `Co-Authored-By: Claude Code <noreply@anthropic.com>`.

## Cluster Task Procedure (executed verbatim by every cluster task below)

1. **Research:** using web search/read tools, compile `cluster-<n>-facts.md` in the SDD workspace: for each article in the task's table, collect its load-bearing numbers with source name + URL (source classes per Global Constraints). Unsourced candidates are dropped here.
2. **RED:** add the cluster's rows to `EXPECTED_KB` in `web/tests/fixtures/kbExpected.ts`; run `cd web && npx vitest run tests/kbContent.test.ts` → FAIL (missing files).
3. **GREEN:** write the article files under `web/src/content/kb/<cluster>/` from the fact sheet, per the house style and frontmatter rules (Global Constraints). File name = the table's slug; frontmatter `category` = cluster slug; suggested `utility/difficulty/minutes` come from the table (writer may adjust ±1 with a note in the report).
4. **Verify:** `cd web && npx vitest run tests/kbContent.test.ts` → PASS; then the full suite `npx vitest run` → all green.
5. **STOP — user checkpoint:** list the new files with their Persian titles and 1-line summaries; ask the user to review (admin KB editor renders markdown; files are also readable directly). Apply flagged fixes, re-run step 4.
6. **Commit:** `git add web/src/content/kb web/tests/fixtures/kbExpected.ts` → `git commit -m "content(kb): cluster <n> <cluster-slug> (<k> articles)"` + attribution line.

## Review Focus

1. **Admin-edited article clobbered by reconciliation** after a cluster merge deploys: admin PUT already sends `source:"admin"` but `saveArticle`'s update branch drops it → pinned by Task 3 (source persists on update) and Task 4 (reconciler skips `source:"admin"` rows even when the file changed).
2. **Renumbered file move leaves a stale duplicate row** (e.g. `gas/01-gas-tariff` → `bills/04-gas-tariff` creates a new row while the old slug lingers in FTS): pinned by Task 4 (orphan seed deleted + FTS dropped) and Task 5 (real-dir smoke asserts the slug set matches exactly).
3. **Lenient/legacy frontmatter** — comma lists instead of JSON arrays, missing new fields, invalid enum values: pinned by Task 2 (parser) and Task 3 (read defaults via `normalizeArticleRow`).
4. **Style drift in produced content** — ASCII digits in Persian prose, missing closing section, wrong word count, thin keyFacts: pinned by Task 5's lint, re-run by every cluster task.
5. **Stale FTS after a reconciliation update** — edited seed article still findable by removed terms: pinned by Task 4 (update re-chunks; old term search returns empty).

let bootReconciled = false;

function filesToInputs(dir: string): { slug: string; input: SaveArticleInput }[] {
  const files: string[] = [];
  const walk = (d: string) => {
    for (const e of fs.readdirSync(d, { withFileTypes: true })) {
      if (e.isDirectory()) walk(path.join(d, e.name));
      else if (e.name.endsWith(".md")) files.push(path.join(d, e.name));
    }
  };
  walk(dir);
  return files.sort().map((f) => {
    const fm = parseFrontmatter(fs.readFileSync(f, "utf-8"), path.basename(f, ".md"));
    return {
      slug: path.basename(f, ".md"),
      input: {
        slug: path.basename(f, ".md"), title: fm.title || path.basename(f, ".md"), bodyMd: fm.body,
        category: fm.category, tags: fm.tags, status: "published" as const, source: "seed" as const,
        utility: fm.utility, difficulty: fm.difficulty, minutes: fm.minutes,
        sources: fm.sources, objectives: fm.objectives, keyFacts: fm.keyFacts,
      },
    };
  });

export function ensureSeeded(db: DB = getDb(), dirs?: string[]): number {
  ensureFts(db);
  if (dirs === undefined && bootReconciled) return 0;
  const searchDirs = dirs ?? seedDirs();
  const dir = searchDirs.find((d) => fs.existsSync(d));
  if (!dir) { console.warn("[kb] no seed directory found; KB starts empty"); return 0; }
  const entries = filesToInputs(dir);
  const fileSlugs = new Set(entries.map((e) => e.slug));
  let inserted = 0;
  for (const { slug, input } of entries) {
    const existing = db.select().from(schema.kbArticles).where(eq(schema.kbArticles.slug, slug)).get();
    if (!existing) { saveArticle(db, input); inserted++; continue; }
    if (existing.source === "admin") continue;
    const changed =
      existing.title !== input.title || existing.bodyMd !== input.bodyMd ||
      existing.category !== input.category ||
      existing.tags !== JSON.stringify(input.tags ?? []) ||
      existing.utility !== (input.utility ?? null) || existing.difficulty !== (input.difficulty ?? null) ||
      existing.minutes !== (input.minutes ?? null) ||
      existing.sources !== (input.sources ? JSON.stringify(input.sources) : null) ||
      existing.objectives !== (input.objectives ? JSON.stringify(input.objectives) : null) ||
      existing.keyFacts !== (input.keyFacts ? JSON.stringify(input.keyFacts) : null);
    if (changed) saveArticle(db, input);
  }
  const seeds = db.select().from(schema.kbArticles).all().filter((r) => r.source === "seed");
  for (const row of seeds) {
    if (fileSlugs.has(row.slug)) continue;
    dropIndex(db, row.id);
    db.delete(schema.kbArticles).where(eq(schema.kbArticles.id, row.id)).run();
  }
  if (dirs === undefined) bootReconciled = true;
  return inserted;
}
